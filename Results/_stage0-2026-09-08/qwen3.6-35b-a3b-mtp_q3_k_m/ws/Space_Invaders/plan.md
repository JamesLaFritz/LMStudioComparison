# Space Invaders — AAA Retro-Futurism Plan

## 1. Core Gameplay: Mathematical Model

### Playfield
- **Dimensions:** World-space X ∈ [−10, 10], Z ∈ [−7, 7] (depth). Y = 0 is ground plane.
- **Camera:** PerspectiveCamera at (0, 12, −14), target (0, 0, 0), FOV 50°. Slight downward angle gives classic arcade perspective with Three.js depth.
- **Player zone:** Bottom third of playfield (Z ≈ 5 to 7). Alien zone: top two-thirds (Z ≈ −6 to −1).

### Player Ship
- **Movement:** Horizontal only (X-axis), clamped to [−9, 9]. Speed = 8 units/s.
- **Shooting:** One projectile active at a time (classic constraint). Fire rate cooldown = 0.3s. Projectile velocity = +25 units/s on Y axis (upward in screen space → mapped to +Y in Three.js world).
- **Lives:** Start with 3 lives. Displayed as ship icons in glassmorphism HUD.

### Alien Formation
- **Grid:** 5 rows × 11 columns = 55 aliens total.
  - Row 0 (top): Type A — "Squid" (cone + sphere composition) — 5 pts each, fastest fire rate.
  - Rows 1–2: Type B — "Crab" (box + cone composition) — 10 pts each, medium fire rate.
  - Rows 3–4: Type C — "Octopus" (sphere + cylinder composition) — 20 pts each, slowest fire rate.
- **Formation movement:** All aliens move as a rigid grid. Horizontal velocity starts at +0.8 units/s. When any alien's X exceeds ±9.5, the entire formation shifts down by 0.35 units and reverses horizontal direction. Speed multiplier increases by 2% per alien destroyed (starting from 1.0).
- **Alien shooting:** Each frame, a random alien has a chance to fire. Probability = baseRate × speedMultiplier. Base rates: Type A = 0.004, Type B = 0.003, Type C = 0.002 per frame at 60fps. Aliens fire downward (−Y direction in Three.js world → toward player).

### Shields / Barriers
- **4 shields** positioned between player and aliens at Z ≈ 1.5. Each shield is a grid of small cubic blocks (3×5 blocks, each 0.2 units). Blocks are destroyed by any projectile passing through them (both player and alien bullets). Uses individual Mesh objects with per-block AABB collision tracking.

### Collision Detection
- **Player bullet vs Alien:** Distance check: `|bullet.pos − alien.pos| < 0.6`. On hit → destroy bullet, destroy alien, spawn particles + score text, add points, trigger camera shake (intensity = 0.15), trigger shockwave ring at alien position.
- **Alien bullet vs Player:** Distance check: `|bullet.pos − player.pos| < 0.7`. On hit → destroy bullet, lose life, screen flash red, camera shake (intensity = 0.4), reset player position. If lives ≤ 0 → game over.
- **Alien bullet vs Shield:** Any block in shield path is destroyed (removed from scene and pool).
- **Player bullet vs Shield:** Same as above — destroys shield blocks.
- **Alien reaches bottom:** If any alien's Z > 4, instant game over.

### Scoring & Progression
- Points: Type A = 50, Type B = 30, Type C = 20 (adjusted for retro feel).
- **Level progression:** When all aliens destroyed → next level with faster base movement, increased alien fire rate, and reshuffled formation. Player keeps score and lives.

## 2. Modern AAA Enhancements (15–20 Specific Implementations)

### 2.1 — Procedural Alien Geometry Composition
Each alien type is a `Group` of composed geometries:
- **Type A (Squid):** Sphere body (radius 0.35, 8×6 segments) + 4 cone tentacles (base radius 0.06, height 0.25) arranged around the bottom hemisphere. Emissive color #ff00ff (magenta).
- **Type B (Crab):** Box body (0.7 × 0.5 × 0.3) + two cone claws extending outward + sphere eyes. Emissive color #00ffff (cyan).
- **Type C (Octopus):** Sphere body (radius 0.4, 12×8 segments) + cylinder legs (6 cylinders, radius 0.04, height 0.3) at the base. Emissive color #ffaa00 (amber).

All use `MeshStandardMaterial` with emissive intensity tuned to 0.8–1.2 so they glow under bloom without washing out.

### 2.2 — InstancedMesh for Alien Grid
Each alien type uses a single `InstancedMesh` with the appropriate base geometry and material. The 55 aliens are split into 3 instanced meshes (one per type). Each frame, update each instance's matrix to reflect formation position. This reduces draw calls from 55+ to 3 for all aliens combined.

### 2.3 — Player Ship Procedural Design
Player ship is a `Group`: main body = tapered box (custom geometry via `BufferGeometry` with vertices forming a fighter shape), wings = two angled boxes, engine glow = cylinder with emissive material pulsing via sine wave on `emissiveIntensity`.

### 2.4 — Neon Grid Floor
Procedural grid using `LineSegments` with `LineBasicMaterial` (color #003366). Generated by iterating X and Z lines across the playfield bounds. Creates classic "Tron" retro-futuristic ground plane.

### 2.5 — Procedural Starfield Background
Particle system of small glowing dots on a large sphere surrounding the scene, or simply a dark gradient background with procedural star texture on a skybox plane. Stars twinkle via per-frame opacity modulation using `Math.sin(time * frequency + phase)`.

### 2.6 — Glassmorphism HUD Overlay
HTML overlay (not Three.js UI): semi-transparent blurred panels (`backdrop-filter: blur(12px)`), neon border accents, glowing text with `text-shadow` and box shadows. Displays score, lives, level, high score. Positioned at top-left, top-right, bottom-center.

### 2.7 — Post-Processing Bloom Pipeline
`EffectComposer` → `RenderPass` → `UnrealBloomPass` (strength: 1.2, radius: 0.4, threshold: 0.6). Threshold tuned so only emissive surfaces glow, not the entire scene. Secondary pass optional: `SMAAPass` for anti-aliasing if performance allows.

### 2.8 — Object Pooling for Projectiles
Generic `ObjectPool<BulletData>` with pre-allocated arrays of bullet state structs (position, velocity, active flag). On fire → `pool.get()` to activate a bullet. On collision/out-of-bounds → `pool.release()` to deactivate. No allocation during gameplay.

### 2.9 — Object Pooling for Alien Projectiles
Same pool system, separate from player bullets. Max pooled projectiles: 30 (15 player + 15 alien).

### 2.10 — Particle Burst System on Kills
On alien death → `ParticleManager.burst(position, count=25, color, speedRange=[2,8], lifetime=0.6s)`. Particles are `InstancedMesh` of small quads or points for performance. Each particle has velocity, life remaining, and fade-out.

### 2.11 — Camera Shake (Trauma-Based)
`CameraShake` system tracks "trauma" value. On alien kill: trauma += 0.3. On player hit: trauma += 0.8. Trauma decays at rate 3.0/s. Each frame, offset camera position by `sin(time * freqX) * intensity * randomOffset`. Frequency increases with intensity for more chaotic shake at high trauma.

### 2.12 — Hit-Stop / Frame Freeze
On alien kill: freeze all game logic for 4 frames (skip update calls). On player death: freeze for 8 frames. Implemented via `HitStop` system that sets a flag in the main loop, preventing physics/input updates while still rendering (for VFX to play out).

### 2.13 — Motion Trails on Projectiles
Each bullet maintains a trail of previous positions (array of last 5 positions). Rendered as fading line segments using `BufferGeometry` with vertex colors (alpha fade from opaque to transparent along the trail). Updated each frame by shifting positions and adding current position at head.

### 2.14 — Shockwave Rings on Deaths
On alien death: spawn a `ShockwaveRing` at the alien's position. Ring is an expanding torus or ring geometry with emissive material, scaling up over 0.5s while fading out. Max concurrent rings: 8 (pooled).

### 2.15 — Floating Score Text
On alien kill: spawn floating text "50" at the kill position that rises upward and fades out over 1.0s. Implemented as HTML overlay elements positioned via `project()` from Three.js Vector3 to screen coordinates, or as sprite textures. Glassmorphism-styled with neon glow.

### 2.16 — Procedural Audio Synthesis
`AudioSynth` using Web Audio API:
- **Player shoot:** Short noise burst + sine sweep (frequency 800→200Hz, duration 0.1s).
- **Alien kill:** Chirp sound (two oscillators, frequency 400→1200Hz, duration 0.15s).
- **Player hit:** Low-frequency rumble (sawtooth, 60Hz, duration 0.3s + distortion).
- **Shield hit:** Metallic ping (sine at 2000Hz with quick decay).
- **Background hum:** Very low oscillator (40Hz sine, volume 0.02) for atmosphere.
All sounds use gain nodes for envelope shaping. No external audio files.

### 2.17 — Level Progression Visuals
Between levels: screen fades to black (via overlay), then displays "LEVEL X" in large glassmorphism text with neon glow, held for 2 seconds before gameplay resumes. Formation speed increases by 15% per level.

### 2.18 — UFO Bonus Event
Every 30–60 seconds (random interval), a special UFO appears at the top edge and moves across the screen. Destroying it awards bonus points (100–500 random). UFO is a distinct instanced mesh with unique geometry (disc shape) and color (#ff0044 red).

## 3. Graphics Pipeline

### Render Pass
```
WebGLRenderer (antialias: true, alpha: false)
  → Scene (dark background #050510)
    → DirectionalLight (intensity 0.3, color #ffffff) — ambient fill
    → AmbientLight (intensity 0.2, color #4466aa) — subtle blue tint
    → Player ship Group
    → Alien InstancedMeshes × 3
    → Shield blocks (individual meshes, pooled for reuse)
    → Grid floor LineSegments
    → Starfield plane
```

### Post-Processing Stack
```
EffectComposer(renderer)
  ├── RenderPass(scene, camera)
  └── UnrealBloomPass(
        resolution: new Vector2(width, height),
        strength: 1.2,           // Bloom intensity — enough to glow, not wash out
        radius: 0.4,            // Spread of bloom
        threshold: 0.6          // Only emissive surfaces above this intensity bloom
      )
```

### Procedural Generation Math
- **Grid floor:** Generate `BufferGeometry` with line segments at every 1.0 unit along X and Z within bounds [−10, 10]. Color: #0a2244 with opacity 0.6.
- **Starfield:** Random positions on sphere surface (radius 50), random sizes (0.02–0.08), random phases for twinkling. Rendered as `Points` with custom shader material or `PointsMaterial`.
- **Shield blocks:** Each block is a small box geometry (0.18 × 0.18 × 0.18). Material: `MeshStandardMaterial` with emissive #44ffaa, intensity 0.3. Blocks are destroyed individually by removing from scene and releasing to pool.

## 4. VFX Implementation Priority Logic

### Camera Shake
- **Trigger:** Alien kill → +0.3 trauma; Player hit → +0.8 trauma; Game over → +1.5 trauma.
- **Decay:** `trauma *= Math.exp(-decayRate * dt)` where decayRate = 3.0.
- **Application:** Each frame, offset camera position by `(random() - 0.5) * intensity * 2` on X and Y axes. Intensity = trauma * maxShakeAmount (maxShakeAmount = 0.15 for kills, 0.4 for player hit).
- **Priority:** Highest — always active when trauma > 0.

### Hit-Stop
- **Trigger:** Alien kill → freeze 4 frames; Player death → freeze 8 frames.
- **Implementation:** `HitStop` system maintains a counter. When counter > 0, the main game loop skips physics updates and input processing but still renders (so VFX particles/shockwaves can animate). Counter decrements each rendered frame.
- **Priority:** High — creates impactful "punch" on kills.

### Particle Bursts
- **Trigger:** Alien death → burst 25 particles; Player hit → burst 15 red particles; Shield block destroyed → burst 8 particles.
- **Management:** `ParticleManager` with hard cap of 500 active particles. Particles are pooled via `ObjectPool<Particle>`. Each particle has position, velocity, color, life (max 0.6s), and size. Updated each frame: position += velocity * dt; life -= dt; if life <= 0 → release to pool.
- **Rendering:** Use `InstancedMesh` of small quads or `Points` with custom shader for performance.

### Motion Trails
- **Trigger:** Every bullet maintains a trail automatically (no explicit trigger).
- **Implementation:** Each bullet stores last 5 positions. Trail rendered as line segments connecting these points with decreasing alpha. Updated each frame by shifting array and pushing current position.
- **Priority:** Medium — adds visual polish to fast projectiles.

### Shockwave Rings
- **Trigger:** Alien death → spawn ring at position; Player death → spawn larger ring.
- **Implementation:** `ShockwaveRing` object with expanding radius (0 → 2.0 over 0.5s), fading opacity (1.0 → 0). Rendered as torus geometry or ring sprite. Pooled, max 8 concurrent.
- **Priority:** Medium — visual feedback on kills.

### Floating Score Text
- **Trigger:** Alien kill → spawn text at position showing points awarded.
- **Implementation:** HTML overlay elements positioned via `camera.project(vector)` to get screen coordinates. Text rises (Y += 2 * dt) and fades (opacity from 1.0 → 0 over 1.0s). Glassmorphism styled with neon glow.
- **Priority:** Medium — score feedback clarity.

### VFX Execution Order Per Frame
1. Check `HitStop` counter — if > 0, skip physics/input, render only (VFX still update).
2. Update all game objects (player, aliens, projectiles, shields).
3. Resolve collisions → trigger VFX events (add to trauma queue, spawn particles, etc.).
4. Update VFX systems (camera shake, particles, shockwaves, trails, score text).
5. Render scene + post-processing.

## Edge Cases & Considerations

1. **Alien formation edge:** When an alien's X exceeds ±9.5, check ALL aliens to ensure the formation reversal is clean (not just the first one that crosses).
2. **Projectile overlap:** Player bullet and alien bullet passing through each other — use distance check with threshold 0.4 for bullet-vs-bullet cancellation.
3. **Shield block destruction order:** Shield blocks are destroyed from both sides simultaneously when hit by any projectile. Need to track which blocks exist and remove them individually.
4. **Gamepad drift:** Apply deadzone (0.2) to gamepad axes to prevent unintended movement.
5. **Memory cleanup on level transition:** When transitioning levels, dispose old alien meshes and create new ones with updated positions/speeds. Ensure no orphaned geometries remain.
6. **UFO timing:** Random interval between 30–60 seconds using `Math.random() * 30 + 30`. UFO moves across top of screen (X from −12 to 12) over ~8 seconds.
7. **Particle cap enforcement:** When ParticleManager reaches 500 active particles, oldest particles are released (FIFO) to make room for new bursts.
8. **Frame rate independence:** All movement and physics use `dt` (delta time) for frame-rate independence. HitStop uses fixed frame counts rather than time.
