# Space_Invaders — Production Implementation Plan

## 1. Locked scope and product target

`Space_Invaders` will be the only game implemented. It will be a complete, finite nine-wave campaign: the player can start, play, pause, lose lives, clear waves, reach a real victory state after wave 9, lose either by exhausting lives or by an alien invasion, and restart cleanly.

The presentation target is a crisp 2.5D orbital-defense diorama. The authoritative game remains a deterministic two-dimensional simulation on the classic 224×256 logical raster. Three.js renders that simulation as shallow procedural 3D geometry with layered depth, metallic PBR surfaces, restrained neon emission, reactive lighting, and cinematic feedback. Rendering, VFX, DOM UI, and audio can observe simulation state but cannot mutate gameplay state.

Non-negotiable constraints:

- Vanilla JavaScript, native ES modules, Vite, and Three.js only for the game runtime.
- Handwritten fixed-point motion, collision, and response; no physics engine or physics wrapper.
- No downloaded models, images, fonts, music, or sound files. Geometry, textures, environment lighting, particles, and audio are generated by code.
- Every visible scene mesh uses `MeshStandardMaterial`. Shader materials internal to Three.js post-processing and PMREM are the only unavoidable exception.
- `EffectComposer`, `RenderPass`, `UnrealBloomPass`, and `OutputPass` are mandatory and remain active at every quality tier.
- All entities, projectiles, particles, trail segments, shockwaves, score labels, and transient lights use fixed-capacity pools.
- A single particle manager enforces an absolute maximum of 500 active particles.
- Only `src/Space_Invaders/` contains game-specific code. `src/shared/` contains systems that can be reused by the other named games without importing this game.
- No placeholder functions, unresolved imports, speculative interfaces, hidden external assets, or files for another game.

## 2. Definition of done

The implementation is complete only when all of the following are demonstrated:

1. `npm install`, `npm test`, and `npm run build` succeed without warnings caused by project code.
2. A Vite dev or preview session boots to a useful title screen with no console error or failed network request.
3. Keyboard and Gamepad API controls can start a campaign, move, shoot, pause, resume, and restart.
4. The normal loop reaches wave clear, respawn, victory after wave 9, life-loss game over, and invasion game over.
5. Collision uses swept handwritten logic and cannot tunnel through an alien, shield cell, projectile, player, saucer, or boundary.
6. All six required VFX are visible during normal play: trauma camera shake, procedural particle bursts, hit-stop, motion trails, shockwave rings, and world-anchored floating score text.
7. Every scene mesh passes a runtime material audit for `MeshStandardMaterial`.
8. Particle activity never exceeds 500; no pool grows after construction; pool exhaustion follows a defined reject or preemption policy.
9. Bloom makes emissive accents glow without bleaching ordinary surfaces or obscuring projectile silhouettes.
10. The full playfield remains visible at 1920×1080, 1366×768, 1024×768, and 390×844; DOM HUD elements do not cover the player, bunkers, lowest enemy row, or primary firing lanes.
11. The game pauses safely on page visibility loss, discards catch-up debt on resume, and recovers from WebGL context loss when the browser supports restoration.
12. Geometry, materials, textures, composer targets, event listeners, DOM nodes, and audio nodes are released on final teardown. GPU memory and pool counts plateau across repeated wave and restart cycles.
13. A browser playtest captures and inspects title, normal play, heavy impact, pause, victory, and loss states rather than relying only on DOM assertions.

## 3. Toolchain and dependency policy

The implementation will pin the currently verified package releases rather than use floating ranges:

- Runtime: `three@0.186.0`.
- Development server and production bundler: `vite@8.3.0`.
- Unit tests: Node's built-in `node:test` runner, avoiding another runtime abstraction.

`package.json` will use `"type": "module"` and scripts `dev`, `build`, `preview`, and `test`. Vite's root `index.html` remains the application entry, `base: './'` keeps a static preview portable, and imports use bare `three` plus supported `three/addons/...` paths. A generated `package-lock.json` will lock the dependency graph during implementation.

Browser verification uses the execution environment's external browser-automation/playtest harness, not a shipped game dependency. It drives the Vite preview through the public UI and the development-only debug bridge, captures `artifacts/playtest/{title,play,impact,pause,reduced-motion,high-contrast,victory,life-loss,invasion-loss}.png`, and writes generated `artifacts/playtest/report.md` with console, viewport, context-loss, pool, and memory evidence. These are verification outputs rather than authored runtime modules.

Current Three.js contracts used by this plan:

- Post-processing order is `RenderPass → UnrealBloomPass → OutputPass`; `OutputPass` performs the renderer's tone mapping and output color conversion and therefore stays last.
- `InstancedMesh.setMatrixAt()` and `setColorAt()` require the corresponding `needsUpdate` flag after batched changes.
- Dynamic instance buffers use `DynamicDrawUsage`; moved instances either receive updated bounds or are explicitly non-culled only when they are guaranteed to remain in the visible playfield.
- Every owned geometry, material, texture, render target, composer, and renderer has an explicit disposal path.

## 4. Ownership, clocks, and data flow

### 4.1 One-way architecture

```text
keyboard/gamepad
      ↓
InputController action snapshot
      ↓
fixed 120 Hz host tick
      ↓
SpaceInvadersSimulation (only gameplay authority)
      ├── typed/fixed pools and shield bitfields
      └── fixed-capacity presentation event queue
              ↓
SpaceInvadersPresentation
      ├── Three.js scene adapters
      ├── VFXDirector
      ├── synthesized audio
      └── DOM/CSS UI
              ↓
EffectComposer render + HUD
```

Simulation state never contains `Object3D`, geometry, material, texture, DOM, `AudioNode`, or browser-event references. Render objects never serve as colliders. The scene adapter consumes stable entity IDs and fixed-point coordinates, while presentation-only animation may add bounded local offsets that never feed back into collision.

### 4.2 Logical and render coordinates

- Simulation raster: `x ∈ [0,224]`, `y ∈ [0,256]`, with positive Y upward.
- Fixed-point representation: Q8 integers, `FP_ONE = 256` subpixels per logical pixel.
- Render mapping: `worldX = (logicalX - 112) × 0.1`, `worldY = (logicalY - 128) × 0.1`; gameplay meshes remain near `z = 0`.
- Camera-safe bounds include a small margin around the 22.4×25.6 world-unit raster.
- With viewport aspect `a`, orthographic half extents are:
  - `halfHeight = max(13.3, 11.7 / a)`
  - `halfWidth = halfHeight × a`
- The playfield is never cropped. Wide screens reveal additional procedural space; portrait screens retain the full field and collapse the HUD.

### 4.3 Clocks

- `WebGLRenderer.setAnimationLoop()` supplies real display frames.
- `FixedStepLoop` advances a `1/120 s` host tick, clamps one real-frame delta to `250 ms`, and performs at most 30 catch-up ticks. Any remainder beyond that bound is dropped and recorded; gameplay slows rather than skipping simulation steps.
- `hostTick` starts at 0 for a fresh campaign and increments at the end of every fixed callback, including a callback consumed by hit-stop. It does not run while the outer loop is suspended for pause or context loss.
- `modeTick` resets to 0 on every simulation-state entry and advances at the end of each non-hit-stopped `READY`, `PLAYING`, `PLAYER_DYING`, and `WAVE_CLEAR` callback. It drives those states' transition timers. `TITLE`, `PAUSED`, `VICTORY`, and `GAME_OVER` do not advance it.
- `worldTick` starts at 0 for a fresh campaign, is preserved through deaths and waves, and advances only at the end of an unblocked `PLAYING` callback.
- Gameplay phases are evaluated from the pre-increment `worldTick`. The player/formation 60 Hz pulse runs when `(worldTick & 1) === 0`; enemy slot phase is `worldTick % 3`, producing an exact 40 Hz opportunity per slot.
- VFX, camera recovery, UI transitions, and audio envelopes use unscaled real time. Projectile trails emit only when a projectile's authoritative simulation position changes.
- Page hide, blur, context loss, and pause clear held inputs and reset the accumulator timestamp; lost wall time is never simulated on resume.

### 4.4 Authoritative fixed-tick order

`SpaceInvadersSimulation.stepHostTick()` uses one explicit order so simultaneous results cannot depend on module call order:

1. Increment no counters yet; sample the current pre-increment `hostTick`, `modeTick`, and `worldTick` phases.
2. If hit-stop is active, decrement its remaining host ticks, increment `hostTick`, and return. Pause/context suspension prevents this callback entirely.
3. For a non-`PLAYING` timed mode, advance only that mode's transition rule, then increment `modeTick` and `hostTick` and return.
4. Copy every moving pool slot's current fixed-point coordinates into its previous coordinates.
5. Consume the buffered action frame. On the 60 Hz phase, integrate player movement and optionally spawn a player shot marked `justSpawned`.
6. On the 60 Hz phase, service one alien. If service wraps the rack, apply its horizontal/drop step, toggle pose, erode overlapped bunker cells, and latch invasion immediately.
7. Evaluate the saucer timer/channel reservation and the current enemy-shot slot's fire decision. A projectile spawned in this tick remains stationary until its next eligible phase, even if its shooter dies later below.
8. Move non-new player/enemy projectiles on their assigned phases and move an active saucer on the 60 Hz phase.
9. Collect all swept projectile/projectile, bunker, actor, saucer-boundary, and playfield-boundary candidates into the fixed collision buffer.
10. Resolve candidates in Q16 TOI/tie order, validate pool generations, apply bunker craters, mark kills/hits, and accumulate the tick's score awards. Boundary candidates release only projectiles that survived earlier contacts.
11. Apply the full score batch and one-time bonus-life crossing, then release consumed entities and emit fixed presentation events.
12. Arbitrate terminal state in strict order: invasion, player hit, zero living aliens. Latch the maximum-priority hit-stop request rather than summing requests.
13. Increment `worldTick`, then the current mode's `modeTick` if it did not transition, and finally `hostTick`.

This ordering intentionally allows a newly fired hostile projectile to survive its shooter's later death, lets a target at a boundary beat cleanup, applies a bonus life before a simultaneous death decrement, and makes rack erosion precede projectile impacts after the same rack step.

## 5. Core gameplay mathematics

### 5.1 Player

- One pooled defender starts at `(112,20)` with logical half extents `(8,4)`.
- Center X is clamped to `[8,216]`.
- Keyboard input quantizes to `-127`, `0`, or `+127`. Gamepad axis 0 applies deadzone `d=0.18`, then remaps as `sign(x) × ((abs(x)-d)/(1-d))^1.35` and quantizes to signed int8.
- Opposing keyboard directions cancel. The larger absolute value wins when keyboard and gamepad both provide movement.
- At full input, the player advances exactly one logical pixel per 60 Hz pulse. Analog motion accumulates its Q8 remainder so subpixel input is deterministic and drift-free.
- Fire is a buffered press edge. A held key does not repeatedly spawn shots, and a release is required before the next press. The buffer survives display frames that produce no fixed step and is cleared on blur, death, or wave transition.
- The player starts with 3 lives. A score crossing from below 1,500 to at least 1,500 awards exactly one bonus life for the campaign.

### 5.2 Formation and alien service cadence

- One fixed pool contains 55 aliens: 11 columns × 5 rows.
- Stable ID is `row × 11 + column`; row 0 is the bottom row.
- Centers are `x(column)=anchorX+16×column`, `y(row)=anchorY+16×row`.
- Wave 1 begins at `anchorX=32`, `anchorY=136`.
- Collision half-height is 4 logical pixels. Bottom-up row half-widths are `[6,6,5.5,5.5,4]`.
- Bottom-up point values are `[10,10,20,20,30]`.
- Each 60 Hz pulse scans cyclically from `formationCursor+1`, skips dead aliens, and services exactly one living alien. Crossing index `54→0` performs one whole-rack step before servicing the wrapped alien.
- This yields the classic acceleration formula `Tstep(N)=N/60 seconds` for `N` surviving aliens, without a hand-tuned speed lerp.
- Rack horizontal step is 2 pixels. With one alien left, rightward motion is 3 pixels while leftward motion remains 2.
- Bounds are recomputed from living alien AABBs against `[8,216]`; dead outer columns cease to constrain the rack beginning on the next tick.
- If a proposed horizontal step crosses a bound, direction reverses and that same rack step moves one step away from the edge plus an 8-pixel downward drop.
- Every rack step toggles the two-frame alien pose and emits a march event. It also clears every bunker cell overlapped by a living alien.
- Invasion latches if an alien overlaps the player or if `alienCenterY - alienHalfHeight ≤ 24`. Invasion outranks all other terminal results and loses the campaign regardless of spare lives.

### 5.3 Wave progression

- The campaign has nine waves so it consumes the complete starting-height progression and ends with an explicit victory.
- Starting downward offsets are `[0,24,40,48,48,48,56,56,56]`; wave `w` uses `anchorY=136-offset[w-1]`.
- A new wave resets the alien pool, formation direction and cursor, pose, bunkers, projectile slots, active/pending saucer and its spawn timer, fire latches, and presentation transients. Score, lives, bonus-life state, completed-shot parity, saucer-score index, and high score remain.
- Clearing waves 1–8 enters `WAVE_CLEAR`, then `READY` for the next wave. Clearing wave 9 enters `VICTORY`.
- No endless mode or other game variant is included in this build.

### 5.4 Player projectile

- The player projectile pool has capacity 1 and the gameplay limit is also 1.
- Half extents are `(0.5,2)`.
- A shot spawns at `playerY + playerHalfHeight + projectileHalfHeight + 1` and first moves on the next 60 Hz pulse.
- It advances `+4` logical pixels per 60 Hz pulse, equivalent to 240 pixels/s.
- A projectile release—alien, saucer, shield, enemy-shot hit, or ceiling miss—increments the completed-shot counter used by the saucer rules.

### 5.5 Enemy projectiles

Three fixed slots model three distinct classic shot roles; none can grow or allocate a replacement:

- `rolling`: computes zero-based `column=clamp(floor((playerX-anchorX+8px)/16px),0,10)` in fixed point, so an exact midpoint tie selects the column to the right, then uses the lowest living alien in that column.
- `plunger`: cycles the 1-based table `[1,7,1,1,1,4,11,1,6,3,1,1,11,9,2,8]`.
- `squiggly`: cycles indices 6–20 of `[1,7,1,1,1,4,11,1,6,3,1,1,11,9,2,8,2,11,4,7,10]`.
- Table cursors advance even when a selected column is empty. Column search is bottom-up. Plunger is disabled with one alien remaining.
- Each bolt has half extents `(1.5,3)`, moves `-4` pixels on its 40 Hz phase, and moves `-5` when fewer than 9 aliens remain.
- A projectile remains valid if its shooter dies later in the same tick.
- Enemy fire is disabled if any gate holds: mode is not `PLAYING`, the player is invulnerable, no aliens remain, or the 48-pulse respawn-suppression counter is nonzero.
- Every hostile bolt spawns at the selected alien's X and at `alienY-alienHalfHeight-boltHalfHeight-1px`; it initializes `stepCount=1` and does not move until its next assigned 40 Hz phase.

Reload threshold depends on score:

```text
R(score) = 48  when score <= 200
           16  when score <= 1000
           11  when score <= 2000
            8  when score <= 3000
            7  otherwise
```

An inactive slot can spawn on its phase only when every other slot is inactive or has `stepCount>R`; equality remains blocked. Active bolts increment a saturating step counter on each later 40 Hz movement pulse and reset it to zero when released.

### 5.6 Saucer

- One pooled saucer sits at logical Y 232 with half extents `(8,3.5)`.
- Its clock begins only after the formation's first downward drop.
- At 1,536 60 Hz cabinet pulses, or 25.6 seconds, it becomes pending and reloads the timer.
- Pending spawn with at least 8 aliens reserves the squiggly channel and waits until its current projectile is inactive. Squiggly cannot spawn while a saucer is pending, active, or in its hit presentation. If the fleet falls below 8 before spawn, pending is cleared and squiggly resumes; the reloaded clock remains in force.
- It moves 2 pixels per 60 Hz pulse.
- Completed player-shot parity selects direction: odd enters left and travels right; even enters right and travels left.
- Mystery score uses the reachable 15-entry cycle `[100,50,50,100,150,100,100,50,300,100,100,100,50,150,100]`. The initial index is 0. A saucer hit awards `table[index]` before the striking projectile's gameplay completion advances the index. Completed-shot parity and score index persist through player deaths and wave changes; administrative projectile flushing during death/wave teardown does not count as a completed shot.
- A collision TOI before boundary exit scores the saucer; a wave change releases it without an award.

### 5.7 Bunkers

- Four deterministic procedural bunkers are centered at logical X `[40,88,136,184]` around logical Y 48.
- Each bunker is a `22×16` one-bit field stored as `Uint32Array(16)`; only bits 0–21 are legal.
- The initial mask combines a rectangular lower body and elliptical roof, then removes a centered `8×6` lower notch. No image or runtime randomness defines the silhouette.
- Projectile broad phase visits only solid cells intersecting the swept projectile box. Earliest TOI wins; a tie selects the lowest stable cell index `row×22+column`.
- A fixed asymmetric `7×5` crater mask clears an enemy impact downward from the top. A player impact uses its vertical mirror upward from below. The mask clips at bunker boundaries.
- The projectile is consumed even if part of its crater overlaps existing damage.
- Shield population can only decrease during a wave. Alien AABBs erase every overlapped cell during a rack step. A new wave regenerates all four masks.
- Rendering compacts live cells into one fixed-capacity `InstancedMesh` only after a dirty flag; the bitfield remains authoritative.

### 5.8 Swept collision

For moving A against moving B:

```text
r0 = A.previousPosition - B.previousPosition
d  = (A.current-A.previous) - (B.current-B.previous)
h  = A.halfExtents + B.halfExtents
```

Each axis intersects `r0 + t×d` with `[-h,+h]` using slab entry and exit times. If an axis has zero relative motion, it rejects unless the starting coordinate is within the expanded slab. A collision exists when:

`max(txEnter, tyEnter, 0) ≤ min(txExit, tyExit, 1)`.

TOI is quantized to an unsigned integer key `clamp(round(t×65536),0,65536)`, so both endpoints are representable. Candidate records come from a preallocated collision buffer and order by:

`[toiQ16, pairKind, sourcePoolIndex, globallyUniqueTargetKey]`.

`pairKind` priority is projectile-versus-projectile, bunker, actor, then boundary. `globallyUniqueTargetKey` packs target domain before the domain-local stable ID, so player 0, saucer 0, alien 0, and bunker-cell 0 cannot compare equal. Each projectile resolves only its earliest still-valid candidate. Pool generation counters invalidate stale candidates. A start-overlapped projectile resolves at `toi=0`; a target on the playfield boundary beats boundary cleanup. Boundary release is collected as the last-priority TOI candidate and executes only after earlier valid collisions resolve.

Collision matrix:

- Player bolt → enemy bolt, bunker, living alien, saucer, ceiling.
- Enemy bolt → player bolt, bunker, vulnerable player, floor.
- Alien body → bunker erosion and invasion checks only.
- Enemy bolts never damage aliens or the saucer.

All valid score awards and a possible 1,500-point bonus life resolve before terminal arbitration. Final arbitration is invasion, then player hit, then zero aliens. For a simultaneous final-alien/player hit, score and bonus-life crossing apply first, life decrements once, then zero lives enters `GAME_OVER`; otherwise the death presentation completes and proceeds directly to `WAVE_CLEAR`. A simultaneous final kill/invasion remains a loss.

## 6. State machine

```text
BOOT → TITLE → READY(240 ticks) → PLAYING
PLAYING ↔ PAUSED
PLAYING → PLAYER_DYING(120 ticks) → READY | WAVE_CLEAR | GAME_OVER
PLAYING → WAVE_CLEAR(180 ticks) → READY(next wave) | VICTORY
PLAYING → GAME_OVER on invasion
VICTORY/GAME_OVER → TITLE or fresh READY
any mounted state → runtime CONTEXT_LOST overlay → prior safe state after restore
```

- Life is decremented exactly once on entry to `PLAYER_DYING`.
- Nonterminal death preserves formation position, living aliens, and bunker damage; it flushes all projectiles and the saucer.
- A simultaneous last-alien/player hit finishes the death presentation and then advances to wave clear if a life remains.
- Pause, hit-stop, and context loss do not advance formation service, shots, saucer clocks, state timers, or transition timers.
- High score and accessibility/audio preferences persist through safe `localStorage` wrappers. Active mid-wave state is deliberately not saved.

## 7. Eighteen AAA retro-futurist enhancements

1. **Depth-preserving command theater:** Gameplay stays at `z=0`; a plated defense deck, three star bands, nebula plane, distant structures, foreground motes, and manual depth-weighted camera offsets create parallax without corrupting 2D aim.
2. **Sculpted alien castes:** Three 8×6 binary silhouettes, each with two march poses, become beveled extruded micro-prisms merged once at boot and rendered as six fixed-capacity `InstancedMesh` batches.
3. **Rank-specific PBR language:** Top, middle, and bottom castes differ in shape, metalness, roughness, accent layout, and luminance as well as hue, preserving accessibility and threat recognition.
4. **Hero defender craft:** A symmetrical extruded hull, procedural turret, recoil rails, and lathed reactor create a readable player silhouette; recoil and reactor charge are presentation springs, not gameplay motion.
5. **Holographic destructible bunkers:** The authoritative bitfields drive an instanced field of beveled cells with intact/damaged edge treatments, direction-aware craters, and no damage-time geometry creation.
6. **Formation march current:** Every rack step toggles pose, emits the classic audio beat, raises a brief shared emissive accent, and runs a directional diffuse/rim-luminance wave through `instanceColor`. Per-instance color is never incorrectly treated as per-instance emissive intensity.
7. **Reactive defense deck:** Instanced metallic strips replace non-PBR line helpers. Nearby projectiles and impacts create bounded emissive ripples across reusable strip instances.
8. **Procedural deep-space panorama:** Seeded instanced micro-icosahedron stars, monolith silhouettes, and a four-octave value-noise nebula provide depth with no asset request.
9. **Procedural reflection environment:** A small code-painted equirectangular Canvas texture becomes one PMREM environment; the source texture and generator are disposed immediately after conversion.
10. **Distinct projectile grammar:** Player, rolling, plunger, and squiggly shots differ in procedural geometry, width, motion-trail cadence, pulse rhythm, and sound—not color alone—while all collision paths remain linear and deterministic.
11. **Direction-aware hit confirmation:** Impact events carry contact normal, relative velocity, and magnitude; spark cones, fragment launch, pooled light direction, and camera impulse all derive from those values.
12. **Alien death disassembly:** A killed instance hides and emits pooled metallic micro-fragments plus sparks inheriting rack velocity; no mesh is cloned at death time.
13. **Saucer warp lane:** The lathed bonus craft uses emissive torus rims, pooled entry/exit rings, a panned dual-oscillator siren, and a high-priority destruction event.
14. **Threat-state art direction:** A normalized danger value derived from living-alien count and lowest Y shifts rim light toward coral, raises deck pulse cadence, deepens the CSS vignette slightly, and lifts march pitch without altering rules.
15. **Cinematic wave transitions:** Rows materialize in a staggered scale/emission sequence while gameplay is locked; wave clear emits one broad shockwave and score tally before the next `READY` state.
16. **Retro broadcast layer:** Low-opacity CSS vignette, scanline, phosphor-edge, and noise gradients sit above the canvas. They never exceed 0.08 opacity and stop moving under reduced-motion settings.
17. **Low-chrome glass command HUD:** Score/lives and wave/high score occupy compact edge chips; controls are transient; title, settings, pause, victory, and loss use focused glass overlays rather than a dashboard frame.
18. **Adaptive presentation governor:** A rolling frame-time EMA moves among high, auto, and low pixel-ratio/emission/shadow tiers with hysteresis. It never disables bloom, changes simulation, changes pool capacity, or modifies gameplay RNG.

## 8. Graphics and post-processing pipeline

### 8.1 Camera and renderer

- `OrthographicCamera` sits at positive Z and calls `lookAt(0,0,0)`, therefore looking along -Z. Negative Z is background/deck depth and positive Z is foreground VFX. Base transform is restored before applying any camera-shake offset each frame.
- `WebGLRenderer({ canvas, antialias: false, alpha: false, powerPreference: 'high-performance' })`; default-framebuffer antialiasing is intentionally off because normal rendering goes through offscreen composer targets.
- `renderer.outputColorSpace = SRGBColorSpace`.
- `renderer.toneMapping = ACESFilmicToneMapping`.
- `renderer.toneMappingExposure = 0.95`.
- Shadows use `PCFSoftShadowMap` with one tightly bounded 1024² key shadow at high/auto and 512² at low. Only the defender, saucer, bunker field, and defense deck participate.
- Effective pixel-ratio tiers are `min(devicePixelRatio,1.75)`, `1.25`, and `1.0`. Supported composer targets use 4 MSAA samples at high, 2 at medium, and 0 at low; unsupported contexts use 0. Low tier deliberately trades edge AA for fill-rate while retaining bloom.
- `ResizeObserver` supplies CSS dimensions. Renderer and composer receive the same size and effective ratio, then camera bounds are recomputed from the formulas in section 4.2.

### 8.2 Composer

```text
RenderPass(scene, camera)
  → UnrealBloomPass(resolution, strength=0.85, radius=0.32, threshold=0.90)
  → OutputPass()
```

`composer.render(realDelta)` is the only normal rendering path. `OutputPass` remains last. Context restoration rebuilds composer-owned targets and passes before a guarded recovery frame.

Bloom discipline:

- Background and deck accents: emissive intensity `0.25–0.65`, intentionally below threshold.
- Alien and defender accents: `1.2–2.2`.
- Projectiles, score-impact rings, and hot sparks: `2.8–4.0`.
- Impact flash: maximum `5.0` for less than 60 ms.
- Base albedos remain dark and saturated; exposure stays below 1.0; white full-screen flashes are forbidden.
- Selective bloom with replacement materials is not used. A high threshold and HDR emissive values separate emitters from ordinary lit surfaces in one pass.

### 8.3 Lighting

- Cool hemisphere fill around intensity 0.45.
- Neutral directional key around 2.2.
- Cyan/magenta rim directionals around 0.8–1.2, with a small threat-driven color/intensity shift.
- Four preallocated point lights for impacts; admission uses priority and age, with at most the two strongest fully illuminated at once.
- Typical metalness is `0.45–0.8`; roughness is `0.22–0.48`. Beveled normals and rim lighting, not excessive bloom, define silhouettes.

## 9. Procedural asset generation

- **Alien geometry:** Six pose/caste geometries are generated from binary masks. Each occupied mask cell becomes a beveled `ExtrudeGeometry` micro-prism, receives a local transform, and is merged at boot with `mergeGeometries` from `three/addons/utils/BufferGeometryUtils.js`. Geometry is centered and bounds are computed once.
- **Player:** A mirrored `Shape` is extruded for the hull; cylinders form rails/barrel; a low-resolution `LatheGeometry` forms the reactor. All parts use factory-created standard materials.
- **Saucer:** A sinusoidally perturbed radial profile feeds `LatheGeometry`; two `TorusGeometry` rims provide emissive structure.
- **Bunkers:** One shared beveled cell geometry serves a single fixed-capacity instanced batch. A compacted slot-to-cell lookup preserves stable simulation IDs.
- **Projectiles:** Shared cylinder/prism geometries and material presets represent each shot role. Visual corkscrew/pulse animation never changes the straight simulation centerline.
- **Arena:** Thin instanced boxes form the deck grid, avoiding `GridHelper` and its non-standard line material. Distant structures are instanced boxes and prisms.
- **Stars:** Three fixed instanced batches of low-poly icosahedra use separate depth, scale, and luminance distributions.
- **Nebula:** A 512×256 Canvas texture evaluates four-octave value noise `Σ(0.5^o × noise(p×2^o))`, then adds deterministic cyan/magenta density bands and sparse stars.
- **Hull maps:** Canvas-generated albedo/roughness maps combine low-frequency value noise, high-frequency scratches, and deterministic rivets. Color textures use `SRGBColorSpace`; roughness/data textures use `NoColorSpace`.
- **Environment:** A low-resolution code-painted equirectangular texture with navy zenith, cyan horizon, and magenta highlight is converted through `PMREMGenerator` and attached to `scene.environment`. Its deterministic generation recipe is retained as CPU-side configuration so context restoration can recreate the source, regenerate and swap the PMREM target, untrack/dispose the superseded target, and again dispose the temporary source/generator.
- Every gameplay asset geometry, material, and texture is created during scene bootstrap. No shot, hit, death, respawn, wave, pause, restart, or normal frame constructs GPU resources. Debounced renderer/composer resize, quality-tier changes, and context restoration may reallocate renderer-owned targets; context restoration may also regenerate the scene-owned PMREM environment.

## 10. VFX implementation and priority rules

Simulation events carry fixed numeric fields equivalent to `{type, priority, entityId, x, y, normalX, normalY, relativeSpeed, magnitude, score}`. A 256-slot fixed queue stores them without allocating objects. Presentation drains higher priorities first while collision itself remains TOI ordered.

Priority classes:

| Priority | Events |
|---:|---|
| P4 | player death, campaign victory, invasion loss |
| P3 | saucer kill, final alien, wave clear |
| P2 | normal alien kill, heavy bunker erosion, bonus life |
| P1 | projectile intercept, bunker chip, muzzle flash |
| P0 | ambient motes, deck and formation cosmetic pulses |

Per impact, initialization order is particle/ring/score/light acquisition, camera trauma, audio/UI notification, then the already-latched simulation freeze affects the following host ticks. A critical cue that cannot acquire particles must still retain its shockwave, audio, HUD, and camera signal.

### 10.1 Camera shake

- `trauma = clamp(trauma + clamp((relativeSpeed/140)×magnitude,0.03,0.55),0,1)` where speed is in logical pixels/s.
- Amplitude is `trauma²`; trauma decays at `1.8/s` in unscaled real time.
- Independent deterministic noise samples X, Y, and roll near 22 Hz.
- Maximum displacement is 0.28 world units and maximum roll 0.012 radians.
- The camera restores its exact base transform before adding shake, preventing drift.
- Reduced motion scales translation/roll to 20% or disables it when explicitly requested.

### 10.2 Hit-stop

- Hit-stop uses integer host ticks and never accumulates floating-time debt.
- Requests combine with `remainingTicks=max(current,requested)`; they never sum.
- P1 projectile/shield event: 1 tick (8.3 ms).
- P2 alien death: 3 ticks (25 ms).
- P3 saucer/final alien/wave clear: 6 ticks (50 ms).
- P4 player death/victory: 10 ticks (83.3 ms).
- Any single request is capped at 12 ticks (100 ms). Pause and context loss supersede hit-stop.
- While frozen, host ticks and buffered actions remain, but world tick, state timers, fire counters, saucer clock, formation, and projectiles do not advance. VFX and the first impact frame continue in real time.

### 10.3 Particle manager

- Absolute capacity is compile-time constant `500` and cannot be configured higher.
- Preallocated typed arrays hold active flag, generation, priority, age, life, position, velocity, acceleration, drag, scale, spin, color, and particle kind.
- Spark slivers, metallic fragments, and ion motes each use bright/medium/dim age-band `InstancedMesh` banks while sharing one central 500-slot CPU budget. Shared `MeshStandardMaterial` intensity changes by age band instead of pretending `instanceColor` can fade emissive output.
- Motion uses `v *= exp(-drag×dt)` and `p += v×dt + 0.5×a×dt²`; particles migrate through age bands and scale toward zero over normalized lifetime.
- P0 admission stops at 350 active, P1 at 425, P2 at 475, and P3/P4 may address all 500.
- At capacity, a request replaces only the oldest lower-priority slot. Otherwise it is partially fulfilled or rejected. The manager records requested, emitted, rejected, preempted, current, and peak counts.
- Typical burst budgets are muzzle 6, bunker hit 12, alien death 22, saucer 50, player death 120. Wave-clear celebration is scheduled over multiple frames so a single event cannot monopolize the pool.

### 10.4 Motion trails

- 192 fixed trail records are rendered through three age-band `InstancedMesh` batches with bright, medium, and dim shared `MeshStandardMaterial` presets.
- A projectile samples only after moving a minimum logical distance, preventing frame-rate-dependent density.
- Segments migrate among age bands, shrink, and darken over 90–140 ms; no material is cloned and no per-hit opacity object is allocated.
- Frozen projectiles emit no repeated segments.

### 10.5 Shockwave rings

- 24 pooled camera-facing torus records use fixed bright/medium/dim material age bands.
- Normalized age `u` drives `radius=r0+rMax×(1-(1-u)^3)` and thickness scale `1-0.75u`.
- Player death emits two counter-rotated rings; normal alien death emits one small ring; wave clear emits one broad low-opacity ring.

### 10.6 Floating score text

- 32 precreated DOM nodes are projected with `Vector3.project(camera)` and converted from NDC to viewport coordinates.
- Each label animates `translate3d`, scale, and opacity for 0.7 s. Same-frame overflow merges spatially adjacent awards before rejecting lower-priority labels.
- Floating labels are `aria-hidden`; a throttled semantic live region announces life, wave, bonus, victory, and loss without reading every score increment.

## 11. Audio synthesis

Audio unlock is attempted only from a trusted keyboard or pointer activation. Gamepad polling is not assumed to satisfy browser user-activation rules: gamepad-only play may begin silently, while a nonblocking "press any key or click for audio" chip remains until a trusted gesture successfully resumes `AudioContext`.

```text
music bus ----\
sfx bus ------- DynamicsCompressor → master Gain → destination
ambience bus -/
```

- Sixteen prewired oscillator voices, four filtered branches of one looped procedural-noise buffer, and four reserved music voices use priority/earliest-release stealing. Oscillators that cannot be reused after stopping are disconnected on `ended`; long-lived gated voices are reused.
- Player shot: square sweep 880→190 Hz over 80 ms.
- Enemy shot: sawtooth sweep 260→110 Hz with band-pass shaping; the three shot roles vary modulation cadence.
- Alien death: triangle 150→55 Hz plus a 90 ms filtered-noise crack.
- Bunker impact: 35 ms band-pass noise around 1.2 kHz.
- Player death: 420 ms filtered noise plus sine sub-drop 95→32 Hz.
- Saucer: persistent detuned 220/223 Hz tones amplitude-modulated near 6 Hz and panned from logical X.
- Formation march: four low notes triggered by authoritative rack-step events, so tempo accelerates naturally as alien service time falls.
- Wave clear uses a short generated major-sixth arpeggio; victory expands it; loss uses a filtered descending minor sequence.
- Stereo pan is `clamp((logicalX-112)/112,-1,1)`.
- Mute and volume persist safely. Visibility loss and context loss suspend audio; pause ramps the music bus down without destroying the graph.

### 13.2 Frame and GPU targets

- 60 FPS median at 1080p; 95th percentile frame below 20 ms on the target desktop profile.
- Stable 30+ FPS at low tier and 50+ FPS in a representative mobile-sized viewport on capable hardware.
- Normal play under 45 draw calls; peak VFX under 70; under roughly 100k visible triangles.
- No geometry/material/texture creation after bootstrap. No object or array allocation in the fixed update after warm-up.
- Scratch `Vector2`, `Vector3`, `Quaternion`, `Matrix4`, `Color`, candidate records, action snapshots, and event read objects are reused.
- Formation transforms update only on rack-step/pose changes; bunker matrices update only when dirty. Batched changes set `instanceMatrix.needsUpdate` and `instanceColor.needsUpdate` once.
- Persistent user quality mode is `auto`, `forced-high`, or `forced-low`; effective render tier is separately `high`, `medium`, or `low`. Only `auto` participates in the governor: it lowers one effective tier after a 120-frame EMA exceeds 19 ms and restores one tier only after 300 frames below 14 ms. Forced modes remain fixed at their named endpoint. Hysteresis prevents oscillation.

The F3 diagnostics panel reports FPS/EMA, frame/simulation/render ms, dropped accumulator time, substep saturation, draw calls, triangles, programs, textures, geometries, every pool's active/capacity values, full particle admission counters, mode, wave, live aliens, input device, quality tier, context state, event overflow, and deterministic state hash.

### 13.3 Resource ownership and teardown

- `main.js` owns exactly one `SpaceInvadersGame`.
- `SpaceInvadersGame` is the lifecycle/composition root and owns the loop, input, simulation, presentation, profile, audio, UI, renderer host, scene, diagnostics, and one GPU `ResourceTracker`.
- `SpaceInvadersSimulation` exclusively owns mutable gameplay state, entity pools, bunker bitfields, counters, and event/collision queues.
- `SpaceInvadersScene` owns scene/camera/view relationships; its geometries, scene materials, Canvas textures, and PMREM render target register exactly once with the common tracker. The PMREM target's owned `.texture` is not tracked separately.
- `RendererHost` exclusively owns the WebGL renderer, composer, passes, composer render targets, resize observer, and WebGL context listeners. Composer resources are never registered with the scene resource tracker.
- VFX managers own their fixed CPU slots and scene/DOM nodes, while shared GPU assets remain tracker-owned and are not double-disposed.
- The audio engine owns its context, buses, voices, noise buffer, scheduling, and connections.
- UI/input/diagnostics/accessibility objects remove only the DOM and listeners they created.

Final disposal order:

1. Mark the game disposed and stop `setAnimationLoop`/fixed callbacks.
2. Detach input plus game-owned visibility/page listeners. Renderer-owned resize/context listeners remain attached until `RendererHost.dispose()`.
3. Dispose UI, accessibility observers, and diagnostics.
4. Cancel audio automation, stop and disconnect sources, disconnect buses, and close the audio context.
5. Dispose `VfxDirector`, whose `FloatingScoreManager` exclusively removes the 32 pooled score DOM nodes; reset the remaining VFX pools and detach their scene nodes without disposing tracker-owned GPU objects twice.
6. Detach scene views.
7. Call `ResourceTracker.dispose()` once to remove objects and dispose every unique scene geometry, scene material, Canvas texture, and PMREM target.
8. Call `RendererHost.dispose()`, which removes its resize/context listeners and observer, disposes composer passes/targets, render lists, and renderer. `forceContextLoss()` is reserved for final teardown only when supported.
9. Clear retained arrays, callbacks, observers, and references.

### 13.4 Context loss

- Canvas `webglcontextlost` calls `preventDefault()`, blocks the fixed loop, saves the prior runtime mode, releases input, suspends audio, and displays a blocking glass recovery surface.
- On restore, `RendererHost` rebuilds composer targets/passes and reapplies size, ratio, tone mapping, and effective quality tier.
- `SpaceInvadersScene.rebuildEnvironmentAfterContextRestore()` regenerates the procedural equirectangular source and PMREM, swaps `scene.environment`, untracks/disposes the superseded PMREM target, and disposes the temporary source/generator. The scene and VFX managers then mark every instanced matrix/color attribute and remaining procedural texture as needing upload before one guarded recovery frame.
- After a successful frame, the accumulator timestamp resets, the overlay clears, and the prior title/paused/playing state resumes with identical simulation state. No lost wall time is replayed.
- Failed restoration remains blocked with a reload action and never enters a blind error loop.

### 16.1 Unit and deterministic tests

- `FixedStepLoop.test.js`: delta clamping, exact substep count, dropped-time reporting, suspension, clock reset, and no post-dispose callbacks.
- `FixedPool.test.js`: exact capacity, exhaustion, stable slots, generation increment, double-release rejection, reset sanitation, and integrity counts.
- `ParticleBudget.test.js`: absolute 500 cap, admission thresholds, lower-priority preemption, equal/higher-priority protection, deterministic oldest-slot selection, and counter accuracy.
- `Collision2D.test.js`: edge contact, upward/downward sweep, start-overlap, parallel miss, relative-motion projectile interception, no tunneling through a one-pixel cell, Q16 TOI, and stable tie order.
- `InputController.test.js`: keyboard press/release edges, repeat suppression, blur release, deadzone curve, D-pad/axis merge, buffered fire, controller disconnect, and input gating under menus.
- `ShieldField.test.js`: generated golden mask, illegal high bits clear, upward/downward mirrored crater golden bitfields, clipping, repeated impacts, monotonic population, and alien erosion.
- `FormationSystem.test.js`: wrap after exactly 55/10/1 service pulses, ±2 step, one-alien right +3, 8-pixel drop, live-only bounds, pose toggle, and invasion latch.
- `SpaceInvadersSimulation.test.js`: shot caps; score reload thresholds at 200/201, 1000/1001, 2000/2001, and 3000/3001; exact plunger/squiggly cycles; bottom shooter selection; sub-nine projectile speed; saucer pulse 1536/eight-alien gate/parity/300-point entry; one-time bonus life; death preservation; wave reset; simultaneous-hit arbitration; wave-9 victory; zero-life and invasion loss; queue overflow behavior; legal state transitions; and disposal.

Determinism is proven by replaying one seed/input log under 30, 60, 90, and 144 Hz render schedules and asserting an identical FNV-1a state hash every 120 host ticks. The hash covers mode, host/world tick, score, lives, wave, formation anchor/cursor/direction/pose, alive mask, projectile slots and generations, bunker rows, saucer counters/index, bonus flag, and hit-stop state. VFX/procedural-art RNG is a separate stream and never enters this hash.

## 18. Known risks and explicit mitigations

- **Bloom washout:** dark base albedo, threshold 0.90, controlled HDR emission, ACES exposure 0.95, and screenshot review at the most crowded impact state.
- **Visual/collision mismatch:** authoritative transforms snap exactly; presentation squash, pose, and emission animate locally without easing collision position away from the visible target.
- **Projectile tunneling:** previous/current Q8 positions, relative swept AABB, Q16 TOI, generation validation, and boundary-last ordering.
- **Hit-stop catch-up:** world tick freezes while host tick consumes the freeze; the accumulator never stores frozen wall time and simultaneous requests take the maximum.
- **Event/particle overload:** fixed capacities, priority-first draining, lower-priority preemption only, partial fulfillment, and persistent counters.
- **Pool stale state:** generation counters, full reset callbacks, double-release assertions, and invariant checks in development.
- **Memory leaks or double disposal:** one explicit owner per subsystem, a set-based resource tracker, fixed teardown order, and renderer-memory snapshots over repeated resets.
- **Context restoration:** blocking overlay, paused simulation, composer rebuild, GPU dirty flags, guarded recovery render, and unchanged state hash.
- **Audio autoplay:** no `AudioContext` work until an explicit user gesture; failure is nonfatal and leaves the game playable.
- **Gamepad variance:** standard mapping first, deadzone/remap/quantization, disconnect release, keyboard always available, and feature-detected haptics.
- **Portrait readability:** camera never crops; HUD collapses; control hints remain transient; a landscape recommendation may appear without blocking play.
- **Storage denial/corruption:** guarded JSON parse/write with schema defaults; persistence failure never blocks a campaign.
