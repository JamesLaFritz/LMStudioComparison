# Space Invaders — AAA Retro-Futurism Implementation Plan

## 0. Approval Gate and Scope

This document is the complete implementation contract for exactly one game: `Space_Invaders`.

Implementation does **not** begin until the user replies with `Plan approved`. The build will use vanilla JavaScript ES modules, Vite, and Three.js. It will not use React, TypeScript, an external game engine, a physics wrapper, downloaded models, image files, sound files, web fonts, or runtime network assets. All visible WebGL meshes will use `THREE.MeshStandardMaterial`; the shader materials internal to Three.js post-processing passes are the only unavoidable exception. Every model, texture, animation, sound, particle, trail, shockwave, and UI element will be generated by JavaScript, Canvas 2D, CSS, Web Audio, or Three.js primitives.

The result is a complete five-wave arcade campaign with a title screen, playable loop, pause state, explicit victory, explicit game over, restart, high-score persistence, keyboard controls, gamepad controls, audio, responsive presentation, cleanup, automated logic tests, and browser smoke tests.

## 1. Product Target

### Player fantasy

The player pilots the last neon defense cannon on a dark orbital platform while a regimented alien armada descends out of a holographic void. The game preserves the pressure, rhythm, readable lanes, shield erosion, mystery saucer, and accelerating cadence of the 1978 game, but presents them as a polished 2.5D diorama.

### Primary verbs

- Move horizontally.
- Fire upward.
- Read safe lanes through destructible defenses.
- Intercept or evade enemy fire.
- Build a short-lived score combo through accurate, rapid kills.
- Hunt the mystery saucer without losing formation awareness.
- Pause, resume, restart, mute, and navigate all screens with keyboard or gamepad.

### Session shape

- A first-time player reaches action within one confirmation input.
- One wave lasts roughly 45–100 seconds depending on skill.
- Clearing wave 5 produces the campaign victory state.
- Losing all lives or allowing the formation to cross the invasion line produces game over.
- The complete campaign targets a 6–10 minute run.

### Non-goals

- No implementation of any other game in the collection.
- No online leaderboard, account system, backend, loot system, or asset download pipeline.
- No arbitrary rigid-body physics; all collision and motion are purpose-built deterministic arcade math.
- No pointer-aiming or touch control requirement. The responsive layout remains legible on narrow screens, but the required play inputs are keyboard and Gamepad API.

## 2. Architectural Invariants

1. **Simulation is renderer-independent.** Files under `Space_Invaders/simulation/` never import `three`. They own rules, state, entity lifetimes, scores, timers, collision decisions, win/loss decisions, and deterministic random state.
2. **Rendering is an adapter.** Three.js objects mirror simulation state; no mesh is authoritative gameplay state.
3. **Fixed deterministic update.** Gameplay advances at 120 Hz (`1 / 120` seconds). Rendering interpolates between previous and current transforms. A clamped accumulator prevents a background-tab spiral of death.
4. **One-way events.** Simulation writes compact events into a preallocated ring. The composition root drains them once into view, VFX, audio, and UI. VFX randomness has a separate seed and can never perturb gameplay.
5. **Strict pools.** Invaders, bunkers, the player, the UFO, pending enemy attacks, all projectiles, all particles, trail segments, shockwaves, and floating score labels have fixed capacities allocated at startup. No active gameplay entity is created with `new` during play.
6. **Particle ceiling.** `ParticleManager` is the only particle allocator. It owns exactly 500 slots and never exposes a path that can exceed them.
7. **Explicit ownership.** Every geometry, material, texture, render target, audio resource, event listener, animation handle, DOM node, and timer has one owner and a documented `dispose()` path.
8. **No hot-loop garbage.** Update and render paths reuse vectors, matrices, event records, collision records, arrays, and iterator indices. DOM text changes only when values change.
9. **Visible material rule.** Meshes and instanced meshes use `MeshStandardMaterial` exclusively. There will be no `MeshBasicMaterial`, `SpriteMaterial`, `PointsMaterial`, `LineMaterial`, `ShaderMaterial`, raw shader mesh, or canvas-drawn gameplay sprite.
10. **Playfield-first UI.** Persistent HUD remains on the outer edges, consumes substantially less than 20% of the viewport, and leaves the central and lower-middle combat lanes unobstructed.

## 3. Runtime Coordinate System and Timing

### World convention

- `+X`: player-right.
- `+Y`: upward toward the invader starting area.
- `+Z`: toward the camera.
- The authoritative gameplay plane is `Z = 0`.
- Depth on models is visual only and does not affect collision.
- Gameplay horizontal bounds are `x = [-11.5, 11.5]`.
- Player baseline is `y = -8.35`.
- Formation spawn center is `y = 6.65`.
- Mystery saucer lane is `y = 9.35`.
- The formation invasion line is `y = -6.85`.
- Out-of-bounds projectile culling occurs beyond `y = [-10.5, 11.2]`.

### Fixed-step clock

- `FIXED_DT = 1 / 120` seconds.
- A render-frame delta is clamped to `0.1` seconds.
- At most 12 fixed steps are processed per render frame. Excess accumulated time is discarded and reported to diagnostics so returning from a suspended tab cannot simulate seconds of unavoidable deaths.
- `alpha = accumulator / FIXED_DT` drives visual interpolation only.
- Pause stops gameplay accumulation while the renderer, menu, and audio fades remain responsive.
- Hit-stop consumes real fixed steps but supplies a dilated `gameDt` to simulation. Render, UI, camera shake decay, and the bloom pipeline continue so the freeze feels intentional rather than like a dropped frame.

## 4. Core Gameplay Mathematics

### 4.1 State machine

The top-level finite state machine is:

`BOOT -> TITLE -> PLAYING -> WAVE_CLEAR -> PLAYING ... -> VICTORY`

From `PLAYING`, player elimination or invasion enters `GAME_OVER`. `PLAYING`, `WAVE_CLEAR`, `VICTORY`, and `GAME_OVER` may enter `PAUSED` only where meaningful; the pause record stores the previous state. Confirmation on title starts a fresh campaign. Confirmation on victory or game over starts a fresh campaign. `R`/gamepad Y performs an explicit restart from non-title screens.

Transient player-hit sequencing is represented inside `PLAYING` with `player.respawnTimer` and `player.invulnerabilityTimer`, not another top-level state. This keeps formation timing and audiovisual effects coherent while the player cannon is temporarily unavailable.

### 4.2 Player motion

The unified controller returns a horizontal action value `axisX` in `[-1, 1]`.

```text
targetVx = axisX * 9.2 units/s
vx = approach(vx, targetVx, (axisX != 0 ? 42 : 56) * dt)
x = clamp(x + vx * dt, LEFT + halfWidth, RIGHT - halfWidth)
```

This produces immediate arcade intent with a short premium-feeling acceleration ramp. Reversing direction uses the acceleration rate; releasing uses the stronger deceleration rate. Player collision is an axis-aligned rectangle of width `1.38` and height `0.62` centered on the visible cannon body.

The player starts with 3 lives, is capped at 5 lives, and gains an extra life at 3,000 points and each subsequent 5,000-point threshold. After a hit, the player is absent for `0.65 s`, then returns with `1.20 s` of invulnerability. Invulnerability is visible as a deterministic emissive pulse; collision is explicitly disabled during it.

### 4.3 Player firing

- Fire is an edge/held hybrid: pressing fires immediately; holding repeats after cooldown.
- Base cooldown is `0.27 s`.
- At most two player bolts may be active. The backing pool has 8 slots to keep the shared pool reusable and leave room for future rule tuning, but the rules enforce the two-shot gameplay cap.
- Bolt speed is `19.0 units/s` and collision size is `0.16 x 0.58`.
- Each spawned projectile stores current and previous position for swept collision and interpolation.
- A projectile deactivates on one hit, interception, or world exit; the slot returns to its free stack without object destruction.

### 4.4 Invader field

The field contains exactly 55 preallocated invader slots in 11 columns and 5 rows. Each slot stores alive state, row, column, local position, archetype, score value, and two-frame animation phase. Row archetypes and base values are:

| Rows | Archetype | Base score |
|---|---|---:|
| 0 | Squid command unit | 30 |
| 1–2 | Crab assault unit | 20 |
| 3–4 | Octopus drone | 10 |

Initial spacing is `1.55` units horizontally and `1.22` vertically. The formation owns an origin and direction; invader local coordinates never drift.

Formation movement occurs on beats rather than as continuous sliding. Before each beat, the system computes the minimum and maximum `x` among living invaders and predicts the next horizontal step:

```text
waveSpeed = 1 + 0.09 * (wave - 1)
aliveRatio = (max(aliveCount, 1) - 1) / 54
beatInterval = clamp(
  (0.095 + (0.680 - 0.095) * pow(aliveRatio, 0.62)) / waveSpeed,
  0.065,
  0.680
)
horizontalStep = 0.30 + 0.012 * (wave - 1)
dropStep = 0.58
```

If the predicted live extent crosses either gameplay boundary, that beat reverses direction and lowers the origin by `dropStep`; it does not also move sideways. Otherwise it advances by `direction * horizontalStep`. Every accepted beat flips the animation phase and emits one of four marching notes. Rendering eases the old origin to the new origin over the first 72% of the next interval with a smoothstep curve, while collision immediately uses the authoritative new position.

The alive extents, not the original 11-column box, determine edge reversal. Removing an outside column therefore changes marching range exactly as players expect.

### 4.5 Enemy firing and telegraphing

Only the lowest living invader in each nonempty column may fire. Firing opportunities follow a frame-rate-independent Poisson process:

```text
tension = 1 - aliveCount / 55
lambda = min(2.8, 0.42 + 0.13 * wave + 1.18 * tension) shots/s
pShotThisStep = 1 - exp(-lambda * dt)
```

When an opportunity succeeds and capacity allows, eligible shooters receive weights:

```text
distanceWeight = exp(-abs(shooterX - playerX) / 5.0)
weight = 0.35 + 0.65 * distanceWeight
```

A deterministic weighted draw selects the column. It cannot select the last-used column more than twice in succession while alternatives exist. The attack first enters one of 8 pooled telegraph slots for `0.12 s`; the shooter flashes and a sound chirps before the bullet is spawned. If the shooter dies during the telegraph, the intent is cancelled safely.

Enemy projectile capacity is 48, with a gameplay active cap of `min(16, 6 + 2 * wave)`:

- **Pulse bolt:** straight downward; available from wave 1; 70% baseline weight.
- **Weaver bolt:** `x = baseX + 0.34 * sin(phase + age * 8.5)`; available from wave 2; 20% baseline weight.
- **Hunter bolt:** initial normalized vector toward the player's position at fire time, clamped so vertical speed remains dominant; available from wave 3; 10% baseline weight.

Base enemy speed is `6.1 + 0.42 * (wave - 1)` units/s. Patterns adjust speed by at most 8%, and never home after spawn. Projectiles therefore remain readable and deterministic.

### 4.6 Swept collision

All combat collision is hand-written 2D logic. Broad phase uses category-specific fixed arrays and lane-aware checks; no physics engine is introduced.

For a projectile moving from `P0` to `P1`, collision expands the target AABB by projectile half-extents and applies a slab segment test:

```text
D = P1 - P0
tNearAxis = (minAxis - P0Axis) / DAxis
tFarAxis  = (maxAxis - P0Axis) / DAxis
tEnter = max(min(tNearX,tFarX), min(tNearY,tFarY), 0)
tExit  = min(max(tNearX,tFarX), max(tNearY,tFarY), 1)
hit iff tEnter <= tExit
```

Parallel-axis cases use containment rather than division. Among all candidate hits, the smallest `tEnter` wins, so a fast projectile cannot kill an invader behind the first target. The returned collision record includes time, point, and outward normal and is reused rather than allocated.

Collision order per fixed step is:

1. Player bolt vs. UFO.
2. Player bolt vs. invaders.
3. Player bolt vs. enemy projectiles.
4. Player bolt vs. bunkers.
5. Enemy projectile vs. bunkers.
6. Enemy projectile vs. player, if vulnerable.
7. Formation bodies vs. bunkers and invasion line.

Projectile interception destroys both projectiles, awards 5 points, resets neither combo nor fire cooldown, and emits a small spark event. Stable iteration order and first-hit selection prevent a projectile from resolving twice.

### 4.7 Destructible defense bunkers

Four bunkers are preallocated from a 15-by-9 logical cell mask. Each cell is `0.20 x 0.20` world units. The initial silhouette includes a curved crown and a three-cell-high central arch generated by an analytic mask:

```text
outer = normalizedEllipse(x, yTop) <= 1
arch  = abs(x) < archHalfWidth && y < archHeight
alive = outer && !arch
```

Approximately 420–480 cells are alive across all four bunkers depending on boundary sampling; all 540 potential slots always exist in the pool and in one instanced mesh.

On impact, the hit is mapped directly to bunker-local integer coordinates. A directional erosion kernel removes live cells satisfying:

```text
(dx / 1.25)^2 + ((dy - directionBias) / 1.70)^2 <= damageScale^2
```

`directionBias` pushes the crater through the far side of the impact, so upward and downward hits carve different shapes. Wave and projectile type can raise `damageScale` from `1.0` to at most `1.35`. Invaders erase any bunker cell overlapped by their body as the formation descends. At wave transition, 18% of destroyed cells are restored using deterministic shuffled indices, preserving battle history without making late waves hopeless.

### 4.8 Mystery saucer

One fixed UFO slot alternates travel direction and becomes eligible 14–26 seconds after the prior departure or destruction. It traverses the top lane at `4.1 + 0.12 * wave` units/s. A procedural siren pans with its normalized horizontal location.

The award follows a deterministic mystery table `[50, 100, 150, 300]`, indexed by `(playerShotsFired + wave + ufoVisitCount) % 4`. Destruction emits the award in floating world text, a magenta shockwave, particles, hit-stop, and camera trauma. If missed, the UFO leaves without penalty and schedules the next visit.

### 4.9 Score and combo

Invader score is:

```text
waveMultiplier = 1 + 0.10 * (wave - 1)
comboMultiplier = 1 + 0.25 * comboTier       // comboTier 0..12
award = roundToNearest5(baseScore * waveMultiplier * comboMultiplier)
```

An invader kill within `1.35 s` of the previous invader kill increments `comboTier`; otherwise it resets to zero before awarding. The multiplier caps at `4x`. UFO and projectile-interception awards do not extend the combo. Player damage immediately clears it. HUD presentation uses the multiplier only when above `1x`.

High score is updated immediately in memory and persisted only on score change milestones, game over, victory, page hide, or disposal—not every frame.

### 4.10 Wave progression and terminal states

- A wave clears when all 55 invaders are dead. Existing hostile projectiles are neutralized into low-priority particles.
- `WAVE_CLEAR` lasts `1.6 s`, during which simulation combat is disabled but VFX, camera, UI, and audio continue.
- The next wave resets the formation higher, partially repairs bunkers, clears projectile pools, resets player location, raises speed/fire parameters, and retains score/lives.
- Clearing wave 5 enters `VICTORY`; the campaign does not silently become endless.
- `GAME_OVER` occurs when lives reach zero after the death sequence, or the bottom bound of any live invader crosses `-6.85`.
- Invasion produces a distinct terminal event and camera push; it cannot be mistaken for ordinary player death.

### 4.11 Determinism

Campaign start chooses a 32-bit seed from `crypto.getRandomValues` when available and stores it in the simulation snapshot. Tests pass explicit seeds. A small deterministic PRNG supplies enemy shooter selection, UFO delay, mystery scoring inputs, and bunker repair. Cosmetic VFX use an independent PRNG instance. Given the same seed and action stream, gameplay outcomes are reproducible.

## 5. Modern AAA Enhancements (18)

1. **2.5D command-deck diorama.** Classic planar rules are rendered with extruded procedural ships, a perspective camera, foreground rails, a receding deck, fog, and restrained parallax. Gameplay silhouettes remain front-readable.
2. **Procedural voxel alien chassis.** Three alien glyph masks generate merged `BufferGeometry` at startup. Alternating limb cells produce the two classic animation poses without textures or model files.
3. **Physically based neon language.** A centralized palette creates only `MeshStandardMaterial` instances with controlled metalness, roughness, emissive colors, and emissive intensity. Cyan identifies the player, acidic green/amber identify ranks, magenta identifies the UFO, and red-orange identifies lethal fire.
4. **Thresholded cinematic bloom.** `EffectComposer` and `UnrealBloomPass` isolate genuinely luminous values through a high threshold, moderate radius, ACES tone mapping, and restrained exposure. Dark metal stays dark instead of blooming gray-white.
5. **Interpolated marching choreography.** Authoritative beat movement remains discrete, while render interpolation, two-pose geometry swaps, rank-specific micro-bob, and tiny depth cant make the fleet feel mechanical without changing hitboxes.
6. **Voxel shield erosion.** One instanced bunker lattice visually loses exactly the cells destroyed by collision math. Directional craters, falling embers, and partial between-wave repair turn shields into readable battle history.
7. **Reactive holographic arena.** A generated CanvasTexture grid and instanced boundary rails brighten locally in response to shots, edge reversals, and impacts. The implementation updates material intensity/instance color—never a custom shader.
8. **Readable enemy weapon signatures.** Shooter telegraphs, distinct procedural geometry, colors, movement equations, and synthesized timbres distinguish straight, weaving, and aimed fire before it becomes dangerous.
9. **Mystery saucer hunt.** The UFO has a generated lathed silhouette, moving siren, rim lights, deterministic mystery award, special destruction sequence, and projected floating score.
10. **Precision combo system.** Rapid invader kills build a capped multiplier with a peripheral HUD pulse and escalating harmonic layer. Damage clears the chain. The system rewards rhythm without changing classic survival rules.
11. **Trauma-based camera response.** Impact velocity and event severity feed a squared trauma model. Position and rotation noise are applied around a stable camera base, then fully restored each frame so shake never drifts.
12. **Procedural impact and explosion particles.** A centralized 500-slot instanced particle manager emits sparks, hull fragments, bunker dust, projectile clashes, and terminal explosions using pooled transforms and palette-driven PBR emission.
13. **Impact hit-stop.** Heavy kills briefly dilate simulation time while rendering and audio envelopes continue. Priority/merge rules prevent rapid kills from accumulating into an unresponsive game.
14. **Pooled motion trails.** Fast player bolts, enemy weapons, and the saucer deposit instanced trail slivers with fixed lifetime, shrinking scale, and darkening HDR color. No geometry is created per shot.
15. **Pooled shockwave rings.** Torus instances expand on projectile clashes, UFO destruction, player death, last-invader kills, and invasion. Scale and emissive decay replace alpha-sorted transparent sprites.
16. **Projected floating score text.** A fixed DOM label pool follows world positions through camera projection, floats upward, and fades. It handles invader points, UFO awards, combo milestones, and extra lives.
17. **Fully synthesized soundscape.** Web Audio oscillators, filters, gain envelopes, stereo panning, and a generated noise buffer create firing, impacts, explosions, saucer siren, UI cues, wave stingers, and a four-note march whose tempo follows the formation beat interval.
18. **Premium glass cockpit UI and accessibility.** Edge-mounted glass panels, neon borders, compact lives/wave/score readouts, modal title/pause/end screens, ARIA announcements, reduced-motion scaling, shake/flash toggles, mute, responsive breakpoints, and gamepad focus all coexist without covering combat lanes.

## 6. Graphics and Post-Processing Pipeline

### 6.1 Renderer

`RenderPipeline` creates:

```text
WebGLRenderer({
  canvas,
  antialias: true,
  alpha: false,
  powerPreference: 'high-performance'
})
```

Configuration:

- Pixel ratio: `min(devicePixelRatio, 1.75)`; reduced to `1.25` when sustained frame time exceeds the performance threshold and restored only after a long stable interval.
- Clear color: near-black navy `#02040b`.
- `outputColorSpace = THREE.SRGBColorSpace`.
- `toneMapping = THREE.ACESFilmicToneMapping`.
- `toneMappingExposure = 1.05`.
- Shadows are disabled. The scene's contact/depth cues come from geometry, lighting, fog, and floor response; avoiding shadow maps saves fill rate and lifecycle complexity.
- `ResizeObserver` supplies CSS pixel dimensions. Camera and composer resize only when dimensions actually change.
- WebGL context loss prevents the browser default, stops simulation advancement, reveals a DOM recovery panel, and records the prior state. Context restoration reapplies renderer/composer size, marks dynamic instance attributes dirty, hides the panel, and resumes only if the game was previously running.

### 6.2 Composer stack

Imports use the current Three.js addon exports:

```js
import { EffectComposer } from 'three/addons/postprocessing/EffectComposer.js';
import { RenderPass } from 'three/addons/postprocessing/RenderPass.js';
import { UnrealBloomPass } from 'three/addons/postprocessing/UnrealBloomPass.js';
import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';
```

Pass order and initial tuning:

1. `RenderPass(scene, camera)`.
2. `UnrealBloomPass(resolution, 0.90, 0.28, 0.86)` where arguments are resolution, strength, radius, and threshold.
3. `OutputPass()` for output color-space conversion and tone mapping.

Bloom strength can momentarily rise by at most `+0.18` for a terminal blast and eases back exponentially. It never flashes the entire screen white. Non-emissive surfaces remain below the `0.86` luminance threshold; neon emissive intensities generally range from `1.4` to `3.8`. Accessibility flash reduction caps transient bloom at the baseline.

The normal render path is `composer.render(realFrameDt)`, never `renderer.render()` followed by composer. Resize calls both renderer and composer with CSS dimensions and pixel ratio. Disposal stops the loop, disposes passes that expose `dispose()`, disposes composer targets, disposes the renderer, and detaches context/resize listeners.

### 6.3 Camera and composition

- Perspective camera FOV: `38°`, near `0.1`, far `90`.
- Base pose near `(0, 0.7, 28.5)`, looking at `(0, 0.35, 0)`.
- Responsive fit calculates vertical and horizontal FOV coverage of the fixed 25-unit-wide gameplay area plus safe margin, then adjusts camera distance rather than changing gameplay bounds.
- Narrow portrait windows prioritize full horizontal visibility and allow additional empty vertical letterbox space.
- Camera shake applies local position up to `0.30` units and roll/pitch up to `0.018` radians at maximum trauma.
- Wave start performs a short, non-interactive dolly from `z + 1.4` to the base pose; reduced-motion mode removes it.

### 6.4 Lighting

- Low-intensity `HemisphereLight` supplies cool ambient fill.
- A front-offset `DirectionalLight` provides stable metallic highlights.
- Two stationary colored `PointLight`s near the lower deck echo player cyan and warning magenta at low intensity.
- A maximum of three preallocated transient point lights may be reused for major explosions. Their intensity decays; lights are never created during combat.
- The scene uses subtle `FogExp2` to soften deep background stars and deck rails while leaving the gameplay plane crisp.

### 6.5 Procedural geometry

- **Invaders:** 8-by-6 boolean glyph masks. Each occupied bit creates a beveled-looking separated box cell (`0.14` depth, 8% inter-cell gap). Cell geometries for each pose are transformed and merged once with `mergeGeometries` from `three/addons/utils/BufferGeometryUtils.js`; source cell geometries are disposed immediately. Normals and bounds are computed on the merged result. Three archetypes times two poses produce six shared geometries for all 55 slots.
- **Player cannon:** merged box, wedge-like extruded shape, and barrel primitives; the barrel remains a separate emissive mesh so charge/fire pulses do not mutate the hull material.
- **UFO:** a `LatheGeometry` generated from a compact radial profile, a flattened dome, and a torus rim. All profile points are computed in code.
- **Bunkers:** one shared rounded-looking voxel box geometry rendered in a single dynamic `InstancedMesh` with 540 fixed matrices.
- **Projectiles:** shared stretched octahedron/box geometries, one instanced mesh per projectile family.
- **Shockwaves:** shared low-segment `TorusGeometry` instances rotated into the gameplay plane.
- **Particles:** one small faceted geometry shared by the 500-slot manager.
- **Stars:** 192 static instances of one tiny icosahedron geometry. They are environmental instances, not active particle-system slots.
- **Deck rails and pylons:** repeated boxes/cylinders rendered with instancing.

All merge inputs are short-lived startup resources and are explicitly disposed after producing their owned merged geometry.

### 6.6 Procedural Canvas textures

`ProceduralTextures.js` creates canvases in memory and immediately wraps them with `CanvasTexture`:

- **Deck grid:** 512×512 tile with major/minor grid lines, deterministic speckle, corner wear, and a radial energy glow. Pixel intensity combines line distance and seeded noise: `I = major + 0.45*minor + 0.08*noise`, clamped before palette mapping.
- **Metal micro-pattern:** 256×256 tile with deterministic brushed bands and sparse panel marks, used only as a subtle roughness/color modulation where appropriate.

Color textures set `texture.colorSpace = THREE.SRGBColorSpace`; data-like roughness textures remain in the no-color space. Repeat wrapping, mipmaps, and renderer-supported anisotropy are configured once. Every canvas texture is registered with `ResourceTracker` and disposed on teardown. CSS creates scanlines for the DOM overlay; there is no full-screen textured mesh.

### 6.7 Draw-call budget

Target at peak action is under 35 draw calls:

- 6 invader pose/archetype instanced meshes, only the three active pose batches visible at once.
- 1 bunker instanced mesh.
- 3 projectile-family instanced meshes.
- 1 star instanced mesh.
- 2–4 environment instance batches.
- Player/UFO meshes and limited decorative meshes.
- 1 particle instance batch.
- 1 trail instance batch.
- 3 palette shockwave instance batches.
- Post-processing passes.

No per-invader standalone mesh and no per-bunker-cell mesh is permitted.

## 7. Shared VFX Priority and Update Rules

### 7.1 Unified event severities

| Priority | Event examples | Camera trauma | Hit-stop | Particle request | Shockwave |
|---:|---|---:|---:|---:|---|
| 4 Critical | Player death, invasion, final invader, victory | 0.65–1.00 | 90–125 ms at scale 0 | 64–110 | Large |
| 3 Heavy | UFO death, extra life, wave clear | 0.38–0.65 | 65–90 ms at scale 0–0.1 | 42–72 | Medium/large |
| 2 Combat | Invader kill, direct player impact | 0.12–0.32 | 28–45 ms at scale 0.12 | 16–30 | Small |
| 1 Minor | Projectile clash, bunker strike, weapon fire | 0.00–0.10 | 0–22 ms | 4–12 | Optional small |
| 0 Ambient | Trail shedding, arena motes | 0 | none | 0–3 | none |

### 7.2 Camera shake

Impact-normal speed is mapped to impulse:

```text
velocityFactor = clamp((impactSpeed - 4) / 18, 0, 1)
addedTrauma = baseByEvent + velocityFactor * velocityScale
trauma = clamp(trauma + addedTrauma, 0, 1)
trauma = max(0, trauma - 1.8 * realDt)
amplitude = trauma^2
```

Three decorrelated deterministic noise samples drive X, Y, and roll/pitch. The stable camera base transform is copied before offsets each frame, guaranteeing zero drift. New trauma adds but clamps; it does not restart a tween. Reduced-motion settings multiply translational shake by 0.25 and remove rotational shake.

### 7.3 Hit-stop

Hit-stop requests carry priority, duration, and minimum timescale. They merge by severity:

- A higher-priority request replaces the current profile and preserves the larger remaining duration.
- Equal priority takes the maximum duration; durations never add.
- Lower priority is ignored while a stronger freeze is active.
- Priority 1–2 requests have a `45 ms` real-time admission cooldown so multi-hit collisions cannot stutter-lock the game.
- Critical hit-stop is capped at `125 ms`.
- Pause, title, victory menu, game over menu, hidden-document state, and context loss reject new hit-stop.

The profile holds at minimum timescale for 60% of duration, then eases to `1` with cubic smoothstep. UI and Web Audio envelopes use real time. Particle/trail motion uses `lerp(realDt, gameDt, 0.7)` so the world visibly hangs but is not perfectly static.

### 7.4 Particle allocation

`ParticleManager` has exactly 500 preallocated slots and an intrusive free-index stack. Every slot stores active, priority, spawn serial, position, velocity, gravity, drag, angular velocity, age, lifetime, start/end scale, and HDR color in typed arrays.

Allocation behavior:

1. Grant free slots up to the request count.
2. If exhausted, priority 0 requests are dropped.
3. Priority 1 requests may replace only the oldest priority 0 slots.
4. Priority 2 requests may replace priority 0–1 slots.
5. Priority 3–4 requests may replace the oldest strictly lower-priority slots.
6. A request never evicts equal/higher priority and degrades its count rather than exceeding 500.
7. Critical events request a guaranteed core count first, then optional particles; normal gameplay reserves practical headroom because ambient emission is suspended above 400 active slots.

The manager uses one dynamic `InstancedMesh`, updates its matrices and colors, scales inactive instances to zero, flags attributes once after the batch update, and recomputes no per-frame bounds because frustum culling is disabled for this world-sized VFX batch.

### 7.5 Motion trails

`MotionTrailPool` owns 128 fixed sliver slots. A projectile emits only after moving at least `0.22` world units since its last deposit. UFO deposits are slower and wider. Trail age controls scale and HDR color toward black; inactive matrices are zero-scaled. Trail updates never allocate particles and do not count against the 500 spark/explosion slots, but they remain strictly pooled visual entities.

### 7.6 Shockwaves

`ShockwavePool` owns 24 slots distributed across cyan, amber, and magenta instanced torus batches. Each ring stores age, lifetime, origin, start/end radius, and palette. Radius uses `easeOutCubic`; thickness shrinks through nonuniform scale; emissive impression fades by scaling and palette intensity rather than creating transparent sorting artifacts. Critical allocation may reclaim the oldest lower-priority ring.

### 7.7 Floating text

`FloatingTextManager` owns 32 prebuilt DOM elements. Each stores a world position, vertical world drift, lifetime, priority, and style class. Per render frame it projects a reused `Vector3` through the camera, hides labels behind/outside the clip volume, and applies a `translate3d` transform. Critical labels may reclaim oldest low-priority labels. Reduced motion removes lateral pop and shortens travel without removing the information.

## 8. Input Contract

The physical-to-action mapping is centralized and cannot be read directly by simulation systems.

| Action | Keyboard | Gamepad |
|---|---|---|
| Move left/right | A/D or Left/Right arrows | Left stick X or D-pad |
| Fire / confirm | Space, Enter | South/A button |
| Pause / resume | Escape, P | Start |
| Restart | R | West/X or North/Y on end screen |
| Mute | M | Back/Select |

Gamepad axis dead zone is `0.20`; the remaining range is remapped to `[0,1]`. If keyboard and gamepad act simultaneously, the input with larger absolute magnitude wins. Digital edges (`pressed`, `released`) are derived centrally from previous/current action state. Browser repeat events are ignored. `visibilitychange` clears held inputs and auto-pauses active play. Connect/disconnect notices are transient UI chips, not modal interruptions.

## 9. Audio Plan

Audio is locked until the first confirm/fire gesture, then one `AudioContext` is resumed. `SynthAudioEngine` owns a master gain, music gain, SFX gain, compressor, reusable noise buffer, and a bounded active-voice registry. Oscillators are necessarily one-shot Web Audio nodes; on `ended`, each disconnects every node and removes its record. Polyphony is capped at 32 voices, with low-priority oldest-voice stealing.

`SpaceInvadersAudio` defines:

- Four square/triangle march notes tied directly to formation phase and beat interval.
- Player laser: fast descending square oscillator with short filtered noise click.
- Enemy telegraph and three weapon timbres.
- Invader kill: pitch derived from row plus noise transient.
- UFO siren: two detuned oscillators with panner following UFO X.
- Bunker impact: short filtered noise with low gain.
- Player death: layered descending saw/triangle and noise burst.
- Wave clear/victory/game-over chord sequences scheduled against audio time.
- UI confirm/pause cues.

Mute is a gain ramp, not context destruction. Pause filters and attenuates music. Disposal stops active sources, clears scheduled callbacks, disconnects nodes, and closes the context.

## 11. Performance, Pooling, and Memory Ownership

### Fixed capacities

| Resource | Capacity |
|---|---:|
| Invaders | 55 |
| Player entities | 1 |
| UFO entities | 1 |
| Bunker cells | 540 |
| Player projectiles | 8 pool / 2 gameplay active |
| Enemy projectiles | 48 pool / up to 16 gameplay active |
| Pending enemy attacks | 8 |
| Simulation events | 256 ring records |
| Particles | 500 absolute active maximum |
| Trail segments | 128 |
| Shockwaves | 24 |
| Floating labels | 32 |
| Transient point lights | 3 |

### Hot-loop practices

- Entity data uses typed structure-of-arrays storage and integer slot IDs.
- Active loops scan bounded arrays; swap-remove lists are used where they preserve stable gameplay semantics, otherwise fixed-order active flags are scanned.
- Collision candidates and return objects are preallocated.
- Three.js `Matrix4`, `Object3D`, `Vector2`, `Vector3`, `Color`, and quaternion scratch instances are created once per renderer/manager.
- Instance matrices/colors are marked dirty once per mesh per frame, not once per entity.
- HUD setters cache the prior displayed value.
- VFX event records are consumed synchronously and returned to the event ring.

### Resource disposal order

1. Stop `FixedStepLoop` and cancel its animation frame.
2. Stop accepting input; abort keyboard, gamepad, visibility, resize, and context listeners through owned `AbortController`s.
3. Persist the profile/high score.
4. Dispose UI and remove created DOM nodes.
5. Stop and dispose game audio, then shared audio context.
6. Dispose floating labels, VFX managers, and transient lights.
7. Dispose game render adapters and remove their scene groups.
8. `ResourceTracker` removes objects and disposes each unique geometry, material, and texture once.
9. Dispose post-processing passes when supported, composer render targets, and renderer.
10. Clear simulation/event pools and object references.

Development/HMR disposal uses the same path. Restarting a campaign resets pools in place and does **not** reconstruct renderer resources.

### Performance targets

- 60 FPS at 1920×1080 on a typical integrated GPU with device pixel ratio capped at 1.75.
- Under 35 scene draw calls at peak action, excluding post-processing internals.
- Zero monotonic growth in `renderer.info.memory.geometries` or `.textures` across ten campaign restarts.
- No more than 500 active particles under synthetic critical-event stress.
- No long task above 50 ms during ordinary play after initial module evaluation.

## 14. Frame and Event Sequence

### Startup

1. `main.js` obtains required DOM nodes and constructs `Game` inside a guarded bootstrap.
2. `GameUI` builds interface layers first so loading/failure states are always visible.
3. `InputController` installs listeners.
4. `SpaceInvadersSimulation` allocates every gameplay pool and enters `TITLE`.
5. `SpaceInvadersView` creates renderer resources, scene, procedural assets, and render adapters.
6. `SpaceInvadersVfx` creates its fixed visual pools using the view's scene/camera and UI world-text host.
7. `SpaceInvadersAudio` remains locked but ready.
8. `FixedStepLoop` starts; title scene renders immediately.

### Fixed update

1. Poll keyboard/gamepad into one action snapshot.
2. Handle global action edges: confirm, pause, restart, mute.
3. Advance hit-stop with real fixed time and derive `gameDt`.
4. If state permits, update simulation in this strict order:
   - state/transition timers,
   - player motion/fire,
   - formation beat,
   - pending enemy telegraphs/fire,
   - projectile integration,
   - collision/combat,
   - UFO,
   - combo and extra-life thresholds,
   - invasion/wave/terminal checks.
5. Drain simulation events once. Each event is offered in order to audio, VFX, UI, and coordinator logic.
6. Return event records to the ring.

### Render frame

1. Read interpolation alpha and real frame delta.
2. Synchronize fleet, bunker, projectile, environment, and telegraph instance data from simulation.
3. Deposit/update motion trails.
4. Update particles, shockwaves, floating text, transient lights, and camera trauma using allowed VFX time.
5. Restore the camera base pose, apply cinematic offsets, then shake offsets.
6. Diff HUD fields and modal visibility.
7. Update diagnostics and dynamic pixel-ratio recommendation outside critical action.
8. Render exactly once through `EffectComposer`.

## 15. Edge Cases to Implement Explicitly

- Simultaneous final-invader kill and player hit: the invader kill resolves first by collision order; wave clear wins unless the already-resolved player hit consumed the last life, in which case game over wins and no next wave starts.
- Simultaneous UFO and invader overlap along a bolt path: nearest swept hit wins.
- Formation edge invader dies on the reversal beat: extents are recomputed before the next beat, with no stale boundary reversal.
- Shooter dies during telegraph: pending attack is cancelled and slot released.
- Pool exhaustion: spawn request fails gracefully and records a diagnostic counter; no array growth or emergency allocation.
- Multiple bunker cells hit in one crater: each slot deactivates once; duplicate indices do not emit duplicate particles.
- Player respawn lane occupied by a projectile: respawn invulnerability prevents unavoidable damage; projectiles are not secretly deleted except those inside a very small cannon safety radius.
- Held fire through pause/title: edge states are flushed on state change, preventing an accidental shot/confirm cascade.
- Gamepad disconnect while moving: axis returns to zero on the next poll.
- Browser loses visibility: inputs clear and live play pauses.
- Resize to zero-sized canvas: rendering suspends until a positive size returns.
- Context loss during hit-stop or pause: prior logical state is preserved; no duplicate loop begins on restore.
- Restart during active VFX: simulation and visual pools reset in place, floating labels hide, camera trauma clears, composer/resources remain owned.
- Local storage unavailable/corrupt: sanitized defaults are used with no boot failure.
- AudioContext denied or unavailable: gameplay remains fully playable and mute UI reports audio unavailable.
- Reduced motion: shake, UI travel, and cinematic camera motion scale down without removing gameplay telegraphs.
- Very high DPR: capped pixel ratio protects performance and bloom stability.
